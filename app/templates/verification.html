Verification Contract &
Current Trust Boundary

Synapse-Mesh separates a reproducible proof contract from the security boundary used to run it. Those are different claims and are reported separately.

Important execution boundaries

The embedded trusted-fixture runner uses temporary working directories, a restricted environment, process timeouts, and operating-system resource limits where supported. It runs inside the API container. It does not create a separate PID, network, or mount namespace for each job, and it does not attest a read-only root filesystem.

Separately, a host timer runs an exact allowlist of repository-owned fixtures in disposable, network-disabled containers and publishes an artifact only after an independent application-image validation gate. That stronger scheduled path is active, but it is not a general intake runner and does not accept public or crawled code.

Public recipe submissions are stored as DRAFT data and are not executed by the server. Local re-verification remains an explicit code-execution action performed by the operator in an environment they control.

Active: hourly draft maintenance

  • Discovers configured upstream release sources without an LLM.
  • Normalizes and retains candidates only in the draft boundary.
  • Does not rewrite application source, deploy, execute third-party snippets, or promote drafts into curated files.

Active: daily exact allowlist

  • Runs only explicitly configured repository-owned fixtures outside the API request path.
  • Uses a disposable network-disabled container with a read-only root, non-root identity, dropped capabilities, no_new_privs, no bind mounts, and bounded resources.
  • Publishes exact run artifacts only after a separate fail-closed validation step.

Not implemented: public hostile-code runner

  • No public or authenticated endpoint executes submitted or crawled code.
  • A future service would need a separately reviewed intake and build-supply-chain boundary, isolated queues, abuse controls, result quarantine, and adversarial validation.
  • Until that exists, an execution request returns an explicit miss instead of an optimistic verification label.

Discovery without model retraining

Agents can discover the MCP endpoint and tool schemas at runtime through /.well-known/mcp.json. The A2A well-known document is discovery metadata; it is not a claim that a full peer-to-peer task gateway is implemented. Autonomous source collection may propose drafts, but promotion is evidence-gated and does not inherit trust from a source, another recipe, or an AI-generated explanation.
